# ClipLiteSync 移动端开发需求书

> 版本：v1.0（2026-10-08）　状态：**待评审**
> 上游文档：《ClipLite多设备同步-需求分析与可行性方案.md》§7（移动端可行性）、§11（协议基线）
> 配套文档：[mobile-dev-guide.md](mobile-dev-guide.md)（技术方案）、[clip-sync-protocol.md](clip-sync-protocol.md)（协议 v0.2/v0.4 冻结稿）

## 1. 背景与目标

ClipLiteSync 当前已有：Go 服务端（房间制配对、按房间隔离的事件广播）+ Windows 桌面端（全自动剪贴板同步）。移动端的目标是**把手机纳入同一个同步房间**，让"电脑上复制、手机上粘贴"与"手机上复制、电脑上粘贴"成为日常工作流。

**核心预期必须先对齐**：受 Android/iOS 系统限制，手机端**做不到 Windows 端那样的全自动后台同步**（Android 10+ 后台禁止读剪贴板，iOS 更严）。移动端的真实形态是"**准同步**"：

- 打开 App 即自动双向同步（最常用路径）；
- 快捷磁贴 / 分享菜单，不打开 App 也能把手机内容发出去；
- 收到的内容进入 App 内历史列表，点击即复制，可直接粘贴到任何输入框。

## 2. 平台范围

| 平台 | 本期 | 说明 |
| --- | --- | --- |
| Android 8.0+（API 26+） | ✅ 一期主力 | Kotlin 原生 |
| iOS | ❌ 暂缓 | 系统限制更严（前台才可读剪贴板 + 粘贴授权弹窗），待 Android 验证产品形态后再评估 |

## 3. 用户场景（按优先级）

| # | 场景 | 流程 | 优先级 |
| --- | --- | --- | --- |
| S1 | 电脑复制 → 手机粘贴 | 手机打开 App（或从通知/磁贴进入）→ 自动连上 → 最新条目已就位 → 点一下复制 → 去任意输入框粘贴 | P0 |
| S2 | 手机复制 → 电脑粘贴 | 手机复制任意内容 → 打开 App 自动上行（或通过快捷磁贴/分享菜单发送）→ 电脑历史窗口出现并可粘贴 | P0 |
| S3 | 多分组管理 | 5 台设备分两组（如 123 一组、45 一组），各组内互相同步、跨组隔离 | P0（依赖已上线的房间隔离） |
| S4 | 房间成员管理 | 在手机上查看本房间成员、生成配对码邀请新设备、移除自己引入的设备 | P1 |
| S5 | 手机截图发电脑 | 复制/截屏图片 → App 内发送 → 电脑收图 | P1 |

## 4. 功能需求

### 4.1 配对与账号（P0）

1. **首次使用向导**：填服务器地址（支持 `ws://` / `wss://`，记住上次值）→ 两条路径：
   - **加入现有房间**：填 8 位配对码 → 提交加入申请 → 房主确认后自动完成（申请状态轮询展示：待确认/已通过/已拒绝/已过期）；
   - **创建新房间**：一键注册本机为新房间（走 `POST /v1/device/register`），无需管理员创始码。
2. **设备命名**：注册/加入时携带设备名（默认取机型，如 "Pixel 8"），电脑端成员列表可见。
3. **连接状态**：实时显示 已连接 / 连接中 / 已断开（自动重连中），断网自动指数退避重连。
4. **退出房间**：清除本机 token 并断开；服务端吊销后客户端收到 `revoked` 错误要明确提示。

### 4.2 同步（P0）

1. **上行（发送）**：
   - 打开 App 时自动读取系统剪贴板（文本），与本地"已发送"指纹去重后上行；
   - App 内历史列表支持手动重发任意条目；
   - 快捷磁贴（Quick Settings Tile）"发送剪贴板"、系统分享菜单"发送到电脑"（分享文本/图片）。
2. **下行（接收）**：
   - WS 在线推送 + 断线补发（`lastSeq` 持久化，与服务端语义一致：超出缓冲窗口接受缺口）；
   - 收到 `clip.add` 立即落库并刷新列表，**自动把最新一条写入系统剪贴板**（Android 10+ 写剪贴板前台应用无需焦点即可，弹系统提示条"已同步剪贴板"）；
   - 去重规则与服务端协议一致：`syncId` 幂等 + `hash` 查重。
3. **条目类型**：一期支持 **文本（clipType=1）** 与 **图片（clipType=3）**；文件列表（clipType=2）只读展示为文本（`localOnly` 条目标记"仅本机"不可粘贴）；HTML（clipType=5）降级为文本处理。
4. **大小限制**：单条上行默认 ≤ 8MB（可在设置调整，1–32MB），超限给出明确提示；图片下行超限时显示占位卡片。
5. **暂停开关**：上行/下行可分别暂停（对应协议 §4.8）。

### 4.3 历史列表（P0）

1. 本地持久化存储（Room），上限默认 500 条（可配），超出淘汰最旧；置顶条目不淘汰。
2. 列表项显示：内容预览（文本前两行 / 图片缩略图）、来源设备名、时间。
3. 操作：点击复制；长按菜单 → 复制 / 重新发送 / 置顶 / 删除（本地删除）。
4. 顶部搜索框按内容过滤。

### 4.4 房间管理（P1）

1. 成员列表（`GET /v1/device/peers`）：设备名 + 在线状态。
2. 生成配对码（`POST /v1/device/invite`）：大字展示 8 位码 + 倒计时（10 分钟）。
3. 待确认申请（`GET /v1/device/pending`）：允许 / 拒绝。
4. 移除设备（`POST /v1/device/peers/revoke`）：仅限自己引入的设备，二次确认。

### 4.5 设置（P1）

服务器地址、设备名、单条上行上限、历史条数上限、上行/下行开关、清除本地历史、退出房间、关于（版本 / 操作说明跳转）。

## 5. 非功能需求

| 项 | 要求 |
| --- | --- |
| 兼容 | Android 8.0+，主流分辨率与深色模式跟随系统 |
| 隐私安全 | token 存 Android Keystore 加密（EncryptedSharedPreferences）；网络明文仅限局域网，公网必须 `wss://`；剪贴板历史仅存本机 |
| 流量 | 移动网络下大图片（>2MB）默认仅 Wi-Fi 同步（可关闭该限制） |
| 电量 | 前台才有常驻连接；退后台即断开（不保活、无前台服务常驻），依赖断线补发兜底 |
| 崩溃 | 崩溃率目标 < 0.3%；本地日志环形缓冲便于反馈问题 |
| 包体 | APK ≤ 10MB，零重量级依赖 |

## 6. 范围边界（本期不做）

- ❌ iOS；❌ 输入法方案（准自动同步）；❌ 后台无感全自动同步（系统不允许）；
- ❌ 文件本体同步（与桌面端一期口径一致：仅文本清单）；
- ❌ 端到端加密（协议已预留 `enc` 字段，二期）；
- ❌ 删除/置顶事件的跨端同步（协议已有事件类型，移动端先只读不发起）；
- ❌ 应用商店上架：本期以 **直接分发 APK** 为主，不上架 Google Play / 国内商店（上架合规另议）。

## 7. 里程碑与工作量

| 阶段 | 内容 | 预估 |
| --- | --- | --- |
| M1 工程骨架 + 配对 | 工程搭建、协议层（WS/JSON/REST）、配对向导（注册/加入/轮询）、连接状态机 | 4~5 人日 |
| M2 文本同步闭环 | 上行/下行/去重/补发、本地存储、历史列表 UI、自动复制 | 4~5 人日 |
| M3 图片 + 体验 | 图片收发与缩略图、深色模式、Wi-Fi 限制、暂停开关、设置页 | 3~4 人日 |
| M4 便利入口 + 管家 | 快捷磁贴、分享菜单、房间管理（成员/配对码/审批/移除）、打磨与联调 | 3~4 人日 |
| **合计** | | **14~18 人日**（与原方案 §6 估算 15~25 人日吻合） |

服务端预期**零改动或极小改动**：开放注册、配对、房间隔离、WS/REST 均已就绪；若 M3 实测图片链路有瓶颈，可能需要调 `CLIPSYNC_BUNDLE_MAX_MB` 或补充移动端专用限流参数。

## 8. 验收标准

1. 与桌面端组成 2 台真实设备房间：电脑复制文本/图片 → 手机 3 秒内（前台时）可见并可粘贴；反向同理。
2. 飞行模式 10 分钟 → 恢复后自动重连并补发窗口内缺失条目，无重复。
3. 两部手机分属两个房间，互相复制内容不可见（隔离验证）。
4. 配对全流程（注册建房 / 填码 / 房主审批）纯手机端可独立完成，无需电脑操作。
5. 杀进程重启后 token/历史/lastSeq 均恢复，直接可用。

## 9. 待确认问题（需要拍板）

1. **最低 Android 版本**：建议 8.0（覆盖面广）；若你自己的设备都是新机，可提到 10.0 减少适配量。
2. **自动写剪贴板策略**：收到新条目就自动覆盖系统剪贴板（会弹系统"已同步"提示条），还是仅提示、点一下才复制？建议前者。
3. **移动网络大图限制**：默认"仅 Wi-Fi 同步 >2MB 图片"是否符合你的使用习惯？
4. **App 名称与图标**：按惯例沿用 **ClipLiteSync**，桌面端同款蓝色系图标？
5. **历史条数上限**：500 条够不够？手机存储敏感的话可降到 200。
6. **分发方式**：APK 直接安装确认可行（你的手机允许未知来源）？

> 确认以上 6 项后即可进入 M1 开发。技术选型与模块设计见 [mobile-dev-guide.md](mobile-dev-guide.md)。
